# AGENTS.md

## Mission

Ship reliable updates to this actively evolving music player supporting Desktop (Electron), Web, and Mobile (Android/iOS). Act like a proactive pair-programmer: gather context first, make the change end-to-end, and leave the repo in a better state than you found it.

## Quick Reference

- **Apps**: `apps/desktop/electron` (Electron), `apps/web/` (Vite + Axum), `apps/mobile/` (Android/iOS)
- **Shared Code**: `apps/shared/` - Vue code shared between desktop and web frontends (stores, composables, UI components)
- **Rust Core**: `crates/aurelia-core/` (shared logic + native audio), `crates/aurelia-api/` (HTTP API abstraction)
- **Run Commands**: `bun run dev:web`, `bun run dev:desktop`, `bun run build`, `bun run test`
- **Testing Guide**: `TESTING.md` (authoritative commands for all apps)

## Golden Rules

1. **Read first**: Check existing patterns before writing new code.
2. **Modern patterns**: Vue 3 Composition API (`<script setup>`), Tailwind v4, Pinia with `ref/reactive`.
3. **No auto-formatting**: Never run ESLint/Prettier unless explicitly asked.
4. **Bun only**: Use `bun install/add/run/x` - never npm/pnpm/yarn.
5. **Be concise**: Short responses, no emojis in code, sacrifice grammar for clarity.

## Cursor Cloud specific instructions

### System dependencies (pre-installed on VM)

The VM snapshot includes Electron/desktop Linux deps (`libgtk-3-dev`, `libssl-dev`, `libasound2-dev` for the Rust audio backend). Bun and Rust stable are available in PATH.

### Running the web app

`bun run dev:web` generates bindings then starts the Rust backend (port 3000) and Vite frontend (port 5173). The backend compilation can exceed the 30s port-wait timeout on a cold build. If the script errors with "Port 3000 did not become available", start backend and frontend separately:

```bash
cargo run -p aurelia-web-backend &   # wait for "Listening on 0.0.0.0:3000"
cd apps/web/frontend && bun --bun vite
```

The frontend proxies `/api` and `/ws` to the backend on port 3000.

### Testing

- **JS/TS**: `bun run test:js` (Vitest: shared + web + desktop)
- **Rust**: `cargo test --workspace`
- **Lint**: `bun run lint` (ESLint; pre-existing warnings/errors in repo)
- **Typecheck**: `bun run typecheck`
- See `docs/TESTING.md` and `docs/BUILDING.md` for full details.

### Bindings

Bindings are generated by `bun run bindings` (runs `cargo run -p uniffi-bindgen`). The `dev:web` and `build:*` commands auto-generate them. Generated files land in `apps/shared/src/generated/`. Regeneration is fingerprint-cached; use `--force-bindings` to bypass.

### Notes

- The app is a client for Jellyfin/Navidrome servers. Full E2E testing requires a running media server. Unit/integration tests work without one.
- No external database needed; the app uses redb (embedded file-based KV store).
- Desktop playback uses the Rust audio backend in the local Axum process (rodio/symphonia), not Web Audio.
